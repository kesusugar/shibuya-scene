## 1. これは何か

**渋谷スクランブル交差点の、ブラウザで動くインタラクティブな3Dシーン。**
Three.js r0.185 + WebGL2。GitHub Pages に静的配信されている（`kesusugar.github.io/shibuya-scene/`、`master` への push で `.github/workflows/deploy-pages.yml` がデプロイ）。

もともとは**「見るだけ」のビジュアル再現プロジェクト**だった。OSM 由来の地理データから地面・建物・駅・看板・街路設備を組み立て、交通シミュレーションと群衆シミュレーションを走らせ、昼夜の太陽サイクルとポストプロセスをかける、という構成。

そこに最近**プレイヤー操作層が乗った**。徒歩で歩け、車に乗れ、人を轢ける。最終目標はオーナーの言葉で「**GTAのように動くこと**」。ただし現時点では**まだゲームではない** — 操作できる箱庭であって、目的も勝敗もスコアもない。これが最大の未解決課題（§6-A）。

技術スタック: vinext 0.0.50（Next.js 16 互換レイヤ）+ Vite 8 + React 19 + Tailwind v4。
ソースは約 130 ファイル・6800 行。ほぼすべて `.mjs`（素の ES モジュール）で、React/TSX は `app/` の 5 ファイルだけ（`ShibuyaScene.tsx` がシーン全体のオーケストレーションを持つ）。

## 3. アーキテクチャ

### 3.1 モジュールシステム

`src/app/foundation.mjs` の `ModuleSystem`。各シーンシステムは `register(id, {build, update, dispose, onTimeChange})` で登録される。登録済み ID は `MODULES` 配列:

```
geo, data, ground, buildings, station, signs, streetscape, traffic,
life, trains, construction, environment, nightglow, postprocess, perf, camera, debug
```

重要な性質:

- **どれか1つが例外を投げても、そのモジュールだけが disable され、他は動き続ける。** `update` 中の例外も同じ扱い。
- `?only=` / `?skip=` で個別に切れる。バグの切り分けは基本これでやる。
- **新しいシーンモジュールは必ず dispose を実装する。** 非同期ビルド中に disable されたら、完了後に自分を復活させてはいけない（`AGENTS.md` の明文ルール）。

### 3.2 データフロー — model と render の分離

```
public/data/shibuya-scene-data.json   （OSM 由来の正規化済みデータ）
        ↓
src/<area>/model.mjs                  （純粋な幾何モデル。Three にほぼ依存しない）
        ↓
src/<area>/render.mjs                 （Three のメッシュ化）
```

**この分離が最重要。** `model.mjs` は Node のテストから直接呼べるので、`tests/` の大半はブラウザなしで幾何とシミュレーションを検証している。新しいロジックを書くときは、**判定・計算は model 側（またはシミュレーション側）に置き、描画だけ render 側に置く。** そうしないとテストが書けない。

### 3.3 事前生成（static pack）— 事故が起きやすい最重要ポイント

`public/data/shibuya-static-models.json` に、高価な幾何（地面・建物・駅・看板・街路・交通グラフ・歩行者ネットワーク）が事前計算されて入っている。

キーは以下のハッシュ:

- `STATIC_ROOTS` の 9 ファイルと、そこから推移的に import される全ファイル
- `public/data/shibuya-scene-data.json`
- `three` と `polygon-clipping` のロック済みバージョン

```js
// build/static-model-key.mjs
STATIC_ROOTS = [
 'src/ground/model.mjs', 'src/buildings/model.mjs', 'src/station/model.mjs',
 'src/station-detail/model.mjs', 'src/signs/model.mjs', 'src/streetscape/model.mjs',
 'src/traffic/graph.mjs', 'src/life/network.mjs', 'src/quality/static-context.mjs'
]
```

**現在のキー: `25ea9435dd5f8cd888702759468eea2f0a6505f27d3f0d598ee05ad615975260`**

> ⚠️ **`STATIC_ROOTS` 配下（および推移的な import 先）を編集したら、必ず `npm run bake:static` で pack を焼き直す。**
> 忘れると、キーが一致せず**全ユーザーが起動のたびに 18MB 相当の幾何をランタイムで再生成する**。過去に実際に起きていて、誰も気付かないまま放置されていた。ビルドは成功するので、成功を根拠に判断してはいけない。
>
> 変更していないつもりでも、毎回これで確認する:
> ```bash
> node --input-type=module -e "import {staticModelKey} from './build/static-model-key.mjs';console.log(staticModelKey(process.cwd()).key)"
> ```

**起動時間はこのプロジェクトが最も重視する指標。** 「事前生成を維持すること」はオーナーの明示的な要求。

### 3.4 群衆 — 2つの厳しい制約

`src/life/` 配下。

**制約1: プール枠に余裕がない。**

```js
POOL_SIZE = 1978 === QUALITY.high.total  // = 1978
```

high ティアでは**予備スロットがゼロ**。1体を別用途（プレイヤーの分身など）で確保すると、**群衆が実測で薄くなる**。

**制約2: 13 ジオメトリ / 3 マテリアルのインスタンシング契約。**

```js
// tests/r1-crowd-density.test.mjs:19
assert.equal(crowd.stats.geometries, 13);
assert.equal(crowd.stats.materials, 3);
```

内訳は body 4 変種 + head + hair 3 変種 + アクセサリ 5 種。**スケルタルアニメーションは禁止**で、テストが `src/life/render.mjs` のソースから `AnimationMixer` / `Skeleton` / `SkinnedMesh` の文字列を検出したら落ちる。

> ⚠️ **群衆に新しい見た目を足したくなったら、契約を広げずに独立したメッシュを作る。**
> 既にそうなっている実例: プレイヤーマーカー（`src/player/marker.mjs`）、血痕（`src/life/blood.mjs`）、タッチUI、声。血痕は `CircleGeometry` 1つ + `MeshBasicMaterial` 1つの `InstancedMesh` で、何個出ても 1 ドローコール。**同じやり方を踏襲すること。**

### 3.5 シミュレーションとプレゼンテーションの分離 — 演出を足すときの型

`CrowdSimulation` は**メッシュも音も一切持たない**。イベントをキューに積み、アプリ（`app/ShibuyaScene.tsx`）が毎フレーム drain する。

現在あるキュー:

| キュー | 中身 | drain 先 |
|---|---|---|
| `sim.splashes` | 血痕を落とす座標・向き・寿命 | `blood.splash()` |
| `sim.voices` | 誰が・どんな声を・どこで | `crowdVoices.say()` |

```js
// src/life/simulation.mjs — 積む側
this.splashes.push({x, y, z, dx, dz, scale, life});
this.voices.push({id, kind, x, z, urgency});

// app/ShibuyaScene.tsx — 汲む側（毎フレーム、使い終わったら length=0）
```

> ✅ **新しい演出（煙、火花、破片、悲鳴以外の音、UI通知）は、必ずこのパターンで足す。**
> シミュレーション側に Three や Web Audio を import させないこと。テストできなくなる。

### 3.6 プレイヤー層 `src/player/`

| ファイル | 役割 |
|---|---|
| `controller.mjs` | 徒歩の移動・視点。キー／タッチ／ゲームパッドを1つの入力に統合（軸ごとに絶対値が大きい方が勝つ） |
| `vehicle.mjs` | 車の物理・当たり判定・乗降・AI車の乗っ取り。`CAR` 定数に全パラメータ |
| `figure.mjs` | プレイヤーの人体（群衆とは別実装） |
| `marker.mjs` | プレイヤーと車の位置を示すコーン |
| `audio.mjs` | エンジン音・衝突音（合成。音源ファイルなし） |
| `voices.mjs` | 群衆の悲鳴（フォルマント合成。音源ファイルなし） |
| `touch-controls.mjs` | スマホ用の可変位置サムスティックとアクションボタン |
| `diagnostics.mjs` / `pad-probe.mjs` | 実機診断パネル（スマホで読める） |

`vehicle.mjs` の主要な仕掛け:

- `poseOk` — 4輪が車道に乗っているか（縁石は越えられる）＋ 固形物に触れていないか ＋ **他の車と重なっていないか**
- `alertPedestrians(crowd)` — 進行方向の回廊を掃いて、当たりそうな人に `crowd.scatter(p, dx, dz, urgency)` を呼ぶ。**声のトリガもここ**
- `strikePedestrians(crowd)` — 実際の接触。`DODGE_SPEED`（2 m/s）未満では発動しない（群衆がその速度以下では避けないため）
- `takeOver(slot)` — 駐車中の AI 車を自分の車にする。`def` が可変なのはこのため（バンを奪ったらバンの当たり判定になる）

### 3.7 信号 — 構造的な弱点を理解しておくこと

`src/traffic/signals.mjs` の `SignalController` は、**街の全信号で1つの時計を共有**している。どこか1グループが歩行者に占有されている間、**その共有時計が止まる（上限なし）**。

`tests/signal-clearance-cycle.test.mjs` は**この無制限の待ちを意図的に契約として assert している**。上限をかけるとこのテストが落ちる。

実際に起きた障害: 横断中の歩行者が 8 人、交差点の入口で物理的に詰まって永久に動けなくなった → 共有時計が止まる → 止まった時計では位相の残り時間が 0 のまま → 新規の横断admissionが全部拒否される → **交差点から人が消え、車も動かなくなる**。

修正は上限ではなく原因側: `CROSSING_GIVE_UP = 12`（横断中に12秒1歩も動けなかった歩行者はリサイクルする）。7分間の同一シードで、時計の凍結 74%→23%、横断完了 33→151、車の総走行距離 5715m→6699m。

> ⚠️ **歩行者の詰まりは街全体を止める。** 群衆の移動ロジックを触るときは必ずこれを意識すること。

### 3.8 テストの位置づけ

- `npm run test:ci`（146件）が**マージゲート**。`scripts/test-current.mjs` にファイル一覧がある。**テストを追加したらこのリストにも足すこと**（`tests/*.test.mjs` の自動 glob ではない）。
- `npm run test:legacy` は**監査ツールであってゲートではない**。歴史的なステージロックで、「後のステージがまだ存在しないこと」を意図的に assert しているものが複数ある。**これを通すために現在の挙動を弱めてはいけない。**
- `evidence/` 配下は「スクラッチではなく、追跡対象の検証スナップショット」。生成スクリプトを意図的に走らせたときだけ更新する。

## 4. 壊してはいけない不変条件（変更前チェックリスト）

1. **static pack のキーが動いていないか。** `STATIC_ROOTS` を触ったら `npm run bake:static`。
2. **群衆の 13 ジオメトリ / 3 マテリアルが維持されているか。** 新しい見た目は契約の外に。
3. **スケルタルアニメーションを導入していないか。** 文字列レベルで禁止されている。
4. **HIGH / MEDIUM / LOW の3ティアが全部動くか。**
5. **新しいシーンモジュールに dispose があるか。非同期ビルド後に復活しないか。**
6. **信号の「歩行者横断」と「車両流」の分離を壊していないか。**
7. **シミュレーション側に描画・音を持ち込んでいないか。** キュー経由にする。
8. **観察モード（プレイヤーモードでない状態）の挙動を変えていないか。** ゲーム機能は原則プレイヤーモード限定。
9. **サードパーティのブランド資産を許可なくダウンロード／コミットしていないか。** 再構成した図案は「再構成である」と明記する。
10. **起動時間を犠牲にしていないか。**
11. **速度のために品質・人口・広告数を勝手に落としていないか。** オーナーの明示的な禁止事項。
12. **`npm run typecheck` と `npm run test:ci` が通るか。**

さらに運用ルール（`AGENTS.md`）:

- ブランチは `codex/<topic>` / `claude/<topic>` / `human/<topic>`。無関係な作業を1ブランチに混ぜない。
- 他の作業者の作業ツリーの変更を上書き・破棄・stage しない。
- 共有ブランチに force-push しない。
- **push はオーナーが明示的に要求したときだけ。**
- 実装・生成された evidence・共同作業ドキュメントは**別コミットに分ける。**
- FPS・実在の広告在庫・視覚的な受け入れを、根拠なしに主張しない。

## 5. 現状のゲーム部分

**できること**

- 徒歩で歩く／走る。視点操作（マウス・タッチドラッグ・右スティック）
- 車に乗る／降りる。駐車中の AI 車を奪う
- 運転（アーケード寄り＋慣性あり。S = ブレーキ→バック）
- 縁石を越えて歩道に乗り上げる
- 歩行者を撥ねる（吹き飛び 3.6m→12.6m、ピーク高 1.34m のラグドール弧、回転、着地スライド、血痕、14秒後に消えて30秒後に別の場所へ復帰）
- 歩行者が車を避ける（実測で接触を 33% 削減。100% ではない）
- 歩行者が声を上げる（「あぶな！」「きゃーー！」など。合成音声、§3.5 のキュー経由）
- 車が壊れる（衝突ごとに蓄積、最高速と加速が落ちる。11m/s の衝突1回で 31%）
- 自分が AI 車に轢かれる（やり直しボタンが出る）
- カメラシェイク、エンジン音、衝突音
- スマホのタッチ操作（可変位置サムスティック＋アクションボタン）
- ゲームパッド（実機未検証）

**できないこと（＝伸びしろ）**

- **目的・スコア・勝敗が一切ない**
- ダメージが**目に見えない**（数値はあるが煙も凹みも出ない）
- 徒歩中は群衆が完全に無反応（声も回避もしない）
- 警察も通報もない。何をしても咎められない
- 走行中の AI 車は奪えない（駐車中のみ）
- 地図・ミニマップがない
- 環境音（街のざわめき、信号の音響装置）がない
- 建物に入れない（QFRONT の浅い内装のみ）

## 6. 次にやると面白いこと（優先順）

### A. 目的を作る — 最優先 ★★★

**いま最大の問題は「上手い／下手」が存在しないこと。** 操作は気持ちよくなったが、やることがない。

**最小実装: チェックポイント・タイムアタック。** 歩行者ネットワーク（`src/life/network.mjs` の `network.nodes`）が既に街全体の座標付きグラフとして存在するので、そこから 3〜5 点を選んで順に回らせ、時間を測るだけで成立する。**新規アセットゼロ。**

- 入口: 新規 `src/player/objective.mjs` ＋ `app/ShibuyaScene.tsx` のフレームループ
- 目印は `src/player/marker.mjs` のコーンを色違いで流用できる
- シード固定でコース生成すれば、同じコースで競える
- 難易度: 低〜中

### B. ダメージを見せる ★★★

`vehicle.mjs` の `state.damage` は 0〜1 で既に動いていて最高速にも効いているのに、**画面上は何も起きない**。データはあって出口がないだけなので、費用対効果が非常に高い。

- 損傷 40% 超で白煙、70% 超で黒煙（`src/life/blood.mjs` と同じ「1ジオメトリ+1マテリアルのInstancedMesh」パターンで作る）
- ヘッドライト片方が消える（`src/traffic/headlight-glows.mjs` に既存の光源処理がある）
- エンジン音が濁る（`src/player/audio.mjs` の `engine()` に `damage` を渡すだけ）
- **メッシュの変形はやらないこと。** 事前生成とインスタンシングの制約と正面衝突する
- 難易度: 低

### C. 環境音（合成） ★★★

`src/player/audio.mjs` と `voices.mjs` が**音源ファイルなしで音を作る手法の実例**になっているので、同じやり方で街の音が作れる。ライセンス問題が発生しない。

- スクランブルの音響信号（鳥の鳴き声を模した断続音）— 実際の渋谷の象徴的な音
- 交通量に連動した低域のうねり（`traffic.stats.moving` を入力にする）
- 人口密度に連動した群衆のざわめき（`crowd` の近傍人数を入力にする）
- 難易度: 中（音作りは試行錯誤が要る）

### D. 徒歩中の群衆リアクション ★★

`voices.mjs` は既に対応できる。`vehicle.alertPedestrians` に相当するものが徒歩側にないだけ。

- 走って突っ込むと避ける・声を上げる
- 倒れている人の周りに人が集まる（`sim.scatter` の逆で、引き寄せる力を足す）
- 難易度: 低（回避）〜中（群集）

### E. ミニマップ ★★

`network.nodes` と `graph`（交通グラフ）が既に 2D のグラフとして存在するので、Canvas 2D で描ける。3D シーンに触らないので安全。**特にスマホで効く。**

- 難易度: 低〜中

### F. フォトモード ★★

`src/qa/capture.mjs` にキャプチャ機構が既にある（`?qa=1`）。これをプレイヤー向けに出すだけ。景色がこれだけ作り込まれているのに、見せる手段がない。

- 難易度: 低

### G. 走行中の車を奪う（カージャック） ★★

`vehicle.mjs` の `nearestTakeover` / `takeOver(slot)` は**駐車車両用に既に完成している**。動いている車に広げるだけ。ただし車列・信号占有の整合性に影響するので、交通シミュレーション側の理解が要る。

- 難易度: 中

### H. 警察・手配度 ★（要合意）

GTA の核だが、**過去の判断「自由運転・赤信号でも咎めなし」を覆すことになる**（§7）。オーナーの合意なしに進めてはいけない。

技術的には `TrafficSimulation` の AI 車に追跡挙動を足す形になり、既存のプールを流用できる。

- 難易度: 中〜高

### やらない方がいいもの

- **建物内部** — QFRONT 以外に内装がなく、幾何を全部作ることになる
- **車のメッシュ変形** — 事前生成・インスタンシング制約と正面衝突
- **銃器** — アセットとアニメーションが必要で、スケルタル禁止と衝突する
- **録音音声の導入** — ライセンス判断が必要。オーナーの決定なしに進めない

## 7. 過去の判断（覆すならオーナーの合意が要る）

これらは実装の都合ではなく、**オーナーが選んだ仕様**。

| 内容 | 決定 |
|---|---|
| 街路設備（ポール等）に当たったとき | 車が止まる（貫通も破壊もしない） |
| 運転感 | アーケード寄りを先に作り、慣性は後から入れる（現在は有効） |

| AI 車に当たったとき | 止まる（めり込まない） |
| 信号無視 | **咎めなし。自由運転。** ← H を実装するならここを覆すことになる |
| S キー | ブレーキ → 停止後にバック |
| 歩道走行 | 可 |
| 撥ねられた歩行者 | 倒れて消え、しばらくして別の場所に復帰（14秒 / 30秒） |
| 車関連の実装範囲 | **プレイヤーモード限定。観察モードは無改変** |

- 「**とにかく GTA のように動くことが最終目標**」
- 速度のために品質・人口・広告数を勝手に落とさない
- 事前生成を維持する（起動時間が重要）
- **push は明示的な許可があったときだけ**
- PR は明示的に頼まれたときだけ作る
- 変更したら都度スクリーンショットが欲しい（見て指示を出す）

## 8. 検証済み / 未検証（正直な状態）

**測定で裏が取れていること**

- 群衆の信号デッドロックは**このプロジェクトに元からあった不具合**で、車の実装による退行ではない（車の作業前のコミットで同一の測定を回して、バイト単位で同じ出力を得ている）
- 修正後: 時計の凍結 74%→23%、横断完了 33→151、車の総走行距離 5715m→6699m（7分・同一シード）
- 歩行者の回避で接触が 42→28（33%減）
- プレイヤー車が AI 車にめり込むフレーム 33→0（60秒）
- 声: 30秒の走行で `scatter` 1535回 → 実際の発声 92回（66人、1人最大3回）
- 声の波形は `OfflineAudioContext` で全 8 種を測定済み。母音のフォルマント構造が実際に出ている

**検証できていないこと**

- **音を誰も聴いていない。** 開発環境に音声デバイスがない。波形の形が正しいことは言えるが、良い音かは言えない
- **ゲームパッド実機未検証。** 特に Switch Pro コントローラの ZR 半押しがアナログ値を返すか不明
- **FPS。** ヘッドレス環境は SwiftShader で約 0.2fps なので、この環境の数値は無意味。実機実測は 9.4〜17.7fps
- HIGH の昼の目視確認（夜しかやっていない）
- 起動時間の最適化（実機の `?startupTiming=1` の JSON が要る）

**受け入れていること（仕様として残っている限界）**

- 共有時計は今も 23% の時間止まっている（設計どおり）
- 歩行者の回避は 100% ではなく 33%
- 車道を塞ぐと AI 車は今も詰まる（車をどけて約28秒で回復）
- プレイヤーの車は交通監査の対象外
- ダメージは性能にしか効かず、見た目に出ない
